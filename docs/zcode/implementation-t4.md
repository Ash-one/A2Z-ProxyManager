## 1. 交付结果（现在为真的事实）

- **独立顶级导航页「ZCode 账号」（`/zcode-accounts`）**：
  订阅类（JWT）与 API Key 上游账号池拥有与「账号管理」（antigravity Google 池）对等的顶级入口；路由表、`Navbar.tsx` 响应式导航胶囊及 `Settings.tsx` 菜单显示控制完整登记，支持通过 `hidden_menu_items` 独立显隐与持久化。
- **卡片栅格重构与池级汇总**：
  `ZaiKeyPoolEditor.tsx` 由单行式列表全面重构为卡片栅格视图；页头新增池级状态徽章（总账号数、可用数、订阅条目数、异常数）；卡片折叠态展示掩码凭证，展开态支持修改凭证与上游提供商类型（zai / bigmodel / zcode-plan）。
- **「添加账号」子弹窗**：
  OAuth 免密登录（CLI 流程）与凭证手动导入（支持 API Key 与 JWT 智能判别）收纳至「添加账号」弹窗（`AddAccountDialog` 规范），主页面保持轻量只承载卡片查看、状态刷新与额度监控。
- **额度卡片直显与错峰拉取**：
  Plan 订阅条目直接在卡片内渲染余额进度条（模型名、剩余/总量及色阶展示）；进入页面经 1.2s 稳定期按条目 **400ms 串行错峰**拉取；同一账号的配对 API Key 自动共享 JWT 额度缓存；Coins 按钮调整为单卡刷新，点击额度条可打开完整套餐详情与 Raw JSON。
- **提供商配置与分发模式破坏性收敛**：
  - `zai.enabled`（总闸）与 `base_url` 自「API 反代」页整体迁入 ZCode 页面底部「转发调度」配置卡（琥珀底强调样式）；
  - **分发模式收敛为唯一确定性语义**：彻底移除 `dispatch_mode`（off/exclusive/pooled/fallback 四模式）及配置字段，固化为**唯一确定性路由**——当提供商开启且池非空时，GLM 系模型（`glm-*` / `zai:*` / `zcode:*`）确定性路由至 z.ai/zcode 通道，其余所有请求路由至 Google 账号池；提供商关闭时所有 GLM 请求均不进入通道。
- **ApiProxy 页面瘦身**：
  「API 反代」页内 z.ai 提供商卡移除 Key 池管理与调度模式，替换为状态摘要与「前往 ZCode 账号页管理」快捷跳转；保留 MCP 独立配置卡。
- **数据层与 Headless 零破损**：
  数据层持久化于 `proxy.zai.keys` 命名空间；所有 Tauri 命令在 Web 模式（`COMMAND_MAPPING` / `/api/zcode/*`）等效可用；12 种国际化语言包键集全等同步。

## 2. 实现期决策（对提案的修订及理由）

| # | 决策 | 理由 | 授权 |
|---|---|---|---|
| 1 | **登录与导入收进「添加账号」子弹窗** | 对齐 `Accounts` 页交互规范，降低主界面视觉噪声，OAuth 成功后自动关闭弹窗 | 用户审查批准 |
| 2 | **卡片直显额度进度条 + 单卡刷新** | 提升订阅额度可感知性；进入页面自动错峰拉取，无后台常驻轮询，风控面收敛可控 | 用户审查批准 |
| 3 | **转发调度配置自反代页迁入 ZCode 账号页** | z.ai 账号与通道调度配置统一收口，反代页仅保留核心网关参数与 MCP，消除双入口混淆 | 用户审查批准 |
| 4 | **分发模式收敛为 GLM 唯一确定性路由**（破坏性收敛） | 四种 dispatch_mode 概念复杂且历史遗留，消除模式配置误导；GLM 模型直通 z.ai、非 GLM 直通 Google，逻辑单一明确 | 用户审查批准 |
| 5 | **账号卡与配置卡视觉区分** | 账号卡为纯白实体卡，转发调度卡采用琥珀底色与左侧色条，明确区分资产与配置面 | 用户审查批准 |
